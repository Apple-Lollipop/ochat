## Ochat 0.7.2 audio continuity

Checked on Windows x64 on October 25, 2026. User reports a private call ending after seconds/minutes with "Audio device disconnected or failed: A buffer underrun or overrun occurred", using an integrated microphone and speakers.

- Cause confirmed in code: the common CPAL error callback put every notification into the fatal error slot; the worker then stopped and the call health check ended the call. CPAL 0.18.2's WASAPI capture backend reports a discontinuity as ErrorKind::Xrun and continues delivering buffers. This notification does not mean the device disconnected.
- Fix: classify by CPAL ErrorKind rather than matching error text. Xrun and RealtimeDenied are advisory and do not populate the fatal slot. Real failures still reach the existing shutdown path; the first pending fatal error is preserved. No automatic device replacement, stream restart, permission change, protocol change or change to mute/push-to-talk behavior. The callback shared by calls, local microphone tests and notification playback uses this policy.
- Regression baseline: temporary_buffer_glitches_do_not_fail_the_audio_session failed on the original error callback (target/audio-xrun-before-fix.log). New tests inject repeated glitches, a later device failure, invalidated/permission/unknown failures, and exercise the private-call health check to verify call identity, audio session and mute survive glitches while device loss ends the call.
- Final checks: 64 native tests passed, zero failed, two external-network tests ignored across 15 test binaries (target/native-v072-test.log). All 88 UI tests passed (target/ui-v072-test.log). Four focused audio-related tests passed, including the new call-health regression (target/audio-v072-focused.log). Rust formatting checks pass. No UI layout change was made; no new browser layout inspection or public relay test was run for this audio-only fix.
